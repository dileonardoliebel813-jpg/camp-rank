# CampRank AI 购买决策助手项目介绍

## 1. 项目概述

CampRank 是一个面向普通消费者的 AI 购买决策辅助产品，当前聚焦在“户外帐篷”这一具体品类。用户不需要自己逐个对比商品参数、价格、售后和大量评论，只需要选择预算、使用场景和购买侧重点，系统就会输出 3 个购买方案：

- 首选方案：最符合当前需求的商品。
- 低价备选：在满足核心要求的前提下，价格更友好的商品。
- 谨慎选择：仍在预算内，但存在部分风险或参数待确认的商品。

这个项目的核心目标不是简单做商品列表，而是把“用户真实购买决策过程”结构化：预算是否合适、场景是否匹配、重量是否适合携带、防水防风是否可靠、评论里是否有集中风险、售后是否明确，最终给出可解释的推荐结果。

## 2. 产品定位

CampRank 的定位是“垂直品类 AI 选购助手”。它不是通用电商搜索，也不是纯内容推荐，而是一个结合商品结构化参数、评论风险分析、价格信息和用户偏好的购买辅助工具。

适用用户包括：

- 不想花大量时间看评论和比参数的普通消费者。
- 对户外帐篷不熟悉，但有明确使用场景的用户。
- 想在预算内降低踩坑风险的用户。
- 需要对比多个商品真实优缺点的用户。

当前 MVP 选择帐篷品类，是因为帐篷购买决策天然包含多个复杂维度：价格、容量、重量、收纳、搭建方式、防水、防风、售后、评论反馈等，非常适合验证“AI 辅助决策”的产品价值。

## 3. 用户使用流程

用户进入首页后，主要完成三个选择：

1. 选择预算区间
   例如 100-1000 元、1000-2000 元等。

2. 选择使用场景
   例如短途休闲露营、雨天或潮湿环境、多人聚会、步行携带等。

3. 选择购买侧重点
   例如价格优先、售后保障、防水防风、收纳携带、空间匹配、搭建方便等。

提交后，前端会把用户选择传给后端推荐接口。后端根据预算、场景和偏好进行筛选、打分和排序，并返回带有解释字段的推荐结果。前端再把结果转化成用户能理解的三张购买方案卡片。

## 4. 核心功能

### 4.1 按预算筛选

系统会先根据用户预算做硬过滤，价格不在预算范围内的商品不会进入主要推荐结果。这样可以避免出现“看起来很好但用户根本不会买”的推荐。

### 4.2 按场景匹配

不同使用场景对应不同的核心要求：

- 短途休闲露营：更关注综合表现、搭建方便、基础风险。
- 雨天或潮湿环境：更关注防水、防风和相关评论风险。
- 多人聚会：更关注空间、容量和展开面积。
- 步行携带：更关注重量、收纳体积和便携性。

系统不会只按关键词粗略匹配，而是会把场景转化成更具体的判断维度。

### 4.3 多偏好强约束匹配

用户可以同时选择多个购买侧重点，例如“低价 + 售后保障”或“防水防风 + 收纳携带”。系统会逐项判断是否满足，而不是只做一个模糊综合分。

推荐结果会被分成三类：

- `core_match`：核心要求都满足。
- `partial_match`：满足一部分要求，但有缺失项或待确认项。
- `fallback`：预算内可参考，但不适合作为强推荐，需要谨慎。

这样可以让用户看到为什么某个商品被推荐，也能知道哪些商品只是补位参考。

### 4.4 评论风险分析

项目会对评论进行结构化分析，识别与购买决策相关的风险方向，例如：

- 防水、防风相关负面反馈。
- 搭建困难或结构不稳定反馈。
- 闷热、异味、透气性问题。
- 退换货、退款、售后相关风险。
- 评论质量和异常评论风险。

评论不是简单展示数量，而是被转化为可参与排序和解释的风险信号。

### 4.5 参数缺失不编造

这是项目的一个重要边界：如果商品缺少重量、防水、防风、收纳尺寸等关键参数，系统不会为了展示效果把它当作“已满足”。缺失参数会被标记为待确认，并影响推荐层级。

例如：

- 用户选择“步行携带”，但商品没有重量或收纳尺寸，不能被判定为便携。
- 用户选择“防水防风”，但商品缺少防水参数，只能结合评论风险作为辅助，不能直接判定为完全满足。
- 用户选择“多人空间”，但缺少容量或展开面积，会被降级处理。

这个设计保证了推荐结果更可信，也避免 AI 产品常见的“看起来完整但实际编造”的问题。

## 5. AI 与算法设计

CampRank 的 AI 能力不是单一大模型聊天，而是更适合真实业务落地的“规则 + NLP + 可解释排序”组合。

### 5.1 评论 NLP 分析

后端包含评论分析模块，用于从评论文本中提取负面风险、售后反馈、退换货问题、体验缺陷等信息。它会把非结构化评论转化为结构化风险指标，供推荐排序使用。

相关模块包括：

- 负面评论分类。
- 评论质量分析。
- 虚假或异常评论识别。
- 退换货与售后风险分析。
- 小红书等内容平台摘要分析预留。

### 5.2 商品评分模型

系统会综合商品参数、价格、平台信息、评论风险、售后信息等维度进行评分。评分不是只看销量或价格，而是围绕“用户是否适合买”进行建模。

主要评分维度包括：

- 价格竞争力。
- 商品参数完整度。
- 防水、防风、便携、空间等性能匹配。
- 售后和退换货风险。
- 评论风险强度。
- 平台购买可信度。
- 用户偏好匹配度。

### 5.3 强约束推荐排序

推荐逻辑采用“硬门槛优先，综合分排序辅助”的思路：

1. 先按预算过滤。
2. 再按场景和偏好判断核心要求。
3. 将商品分为完全满足、部分满足和补位参考。
4. 在同一层级内再按用户匹配分、数据可信度和综合分排序。

这种设计比单纯的综合分更适合购买决策场景。因为用户选择“防水防风”时，一个便宜但防水风险高的商品不应该排在前面；用户选择“步行携带”时，缺失重量参数的商品也不应该被强行推荐。

## 6. 系统架构

项目采用前后端分离架构：

```text
用户选择预算/场景/偏好
        ↓
React + Vite 前端
        ↓
FastAPI 后端接口
        ↓
推荐排序与强约束匹配
        ↓
商品参数 / 评论风险 / 售后 / 价格数据
        ↓
SQLite 本地数据库
```

### 6.1 前端

前端使用 React + Vite 实现，主要页面包括：

- 首页筛选入口。
- 推荐结果页。
- 商品详情页。
- 价格对比页。

前端重点不是堆技术术语，而是把复杂的推荐结果翻译成用户能理解的购买建议，例如“完全满足”“补位参考”“待确认参数”“主要风险”等。

### 6.2 后端

后端使用 FastAPI，负责数据读取、评分、推荐和接口输出。

主要模块包括：

- 商品接口：提供商品列表和详情。
- 推荐接口：根据预算、场景和偏好返回推荐结果。
- 价格对比接口：处理不同平台价格和购买信息。
- 数据导入模块：支持真实数据和样例数据导入。
- 评分模块：处理商品综合评分、评论风险、售后风险、平台购买分等。
- NLP 模块：处理评论文本分析和风险识别。

### 6.3 数据层

Demo 阶段使用 SQLite，方便本地运行和验证。真实评论数据和本地数据库只保存在本地，不上传到 GitHub 或公开部署平台。

数据来源可以分为两类：

- 本地真实数据：用于本地完整版本验证。
- 公开样例数据：用于开源项目演示和代码结构说明。


## 9. 项目亮点

### 9.1 从真实购买问题出发

项目不是为了展示 AI 而展示 AI，而是从用户买帐篷的真实问题切入：参数多、评论多、风险不透明、选择成本高。系统把这些问题拆成可计算、可解释的决策维度。

### 9.2 推荐结果可解释

每个推荐结果不仅有排序，还会说明：

- 满足了哪些要求。
- 哪些要求没有满足。
- 哪些参数缺失，需要用户确认。
- 为什么它是首选、低价备选或谨慎选择。

这比黑盒推荐更适合高决策成本商品。

### 9.3 尊重数据边界

系统明确区分真实数据、本地数据和公开样例数据。缺失参数不会被编造，真实评论数据不会上传到公开仓库。这一点体现了 AI 产品在数据可信度和隐私边界上的意识。

### 9.4 具备工程完整性

项目不仅有前端页面，还包括后端 API、评分模块、数据导入脚本、测试用例、部署说明和数据边界说明。它更接近一个可持续迭代的产品原型，而不是一次性的页面 Demo。

### 9.5 可扩展到更多品类

虽然当前聚焦帐篷，但整体架构可以扩展到其他高决策成本商品，例如露营车、冲锋衣、户外电源、儿童用品、小家电等。只需要调整品类参数、评论风险词典和推荐规则。

## 10. 当前阶段与后续规划

当前阶段：

- 已完成前后端分离的 MVP。
- 已完成预算、场景、偏好筛选。
- 已完成推荐结果三方案展示。
- 已完成评论风险、售后风险、参数缺失提示等核心能力。
- 已区分本地真实数据和公开样例数据。

后续可以继续优化：

- 引入更多品类。
- 增强评论 NLP 模型能力。
- 接入更稳定的官方商品数据源。
- 增加用户反馈闭环，例如“这个推荐是否有用”。
- 增加多平台价格和优惠稳定性分析。
- 将 SQLite 升级为 PostgreSQL，支持更正式的线上环境。
- 引入大模型生成更自然的购买解释，但仍以结构化证据为基础。

## 11. 一句话介绍

CampRank 是一个面向真实消费决策的 AI 选购助手，通过商品参数、价格、售后和评论风险分析，把复杂商品对比转化为“首选、低价备选、谨慎选择”三种可解释购买方案，帮助用户在预算内更快、更稳地做出购买判断。

## 12. 面试展示建议

展示这个项目时，可以按下面顺序讲：

1. 先讲用户问题：买帐篷时参数和评论太多，普通用户难判断。
2. 再讲产品方案：用户选择预算、场景、偏好，系统输出 3 个购买方案。
3. 再讲 AI 能力：评论风险分析、参数缺失识别、强约束推荐排序。
4. 再讲工程架构：React 前端、FastAPI 后端、SQLite 数据库、评分和 NLP 模块。
5. 最后讲边界意识：真实数据本地保存，公开仓库只放代码和样例，不编造缺失参数。

如果时间很短，可以用这段 30 秒介绍：

> CampRank 是我做的一个 AI 购买决策助手，当前聚焦户外帐篷。用户选择预算、使用场景和购买偏好后，系统会结合商品参数、价格、售后文本和评论风险，输出首选、低价备选和谨慎选择三种方案。它的重点不是简单排序，而是把用户的核心需求变成强约束，明确说明每个商品满足了什么、缺了什么、为什么推荐。项目采用 React + FastAPI + SQLite 架构，包含推荐排序、评论 NLP 风险识别、数据导入和测试体系，同时严格区分真实本地数据和公开样例数据。
