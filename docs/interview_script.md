# CampRank 面试讲解稿

## 1. 项目背景

CampRank 是一个多平台户外帐篷智能消费决策系统，目标用户是 18-28 岁大学生、刚上班族和轻露营新手。帐篷这类商品参数复杂、平台差异大、售后风险高，新手用户很容易只看销量或低价购买，最后遇到漏水、断杆、空间虚标、异味、退款慢、退货麻烦等问题。

所以这个项目不是简单爬虫，而是把多平台数据转化成可解释购买建议的消费决策系统。爬虫只是数据采集层，真正的核心是同款识别、评论可信度、有效差评、优惠稳定性、退货风险折算和场景化评分。

## 2. 技术栈

项目规划使用：

- 后端：Python + FastAPI。
- 数据库：SQLite，后续可扩展 PostgreSQL。
- 数据分析：pandas、jieba、规则词典。
- 采集：requests、BeautifulSoup、Playwright，优先使用开放平台、联盟 API 或公开数据源。
- 前端：React + Vite + Tailwind CSS。
- 测试：pytest 和 npm run build。

第一版可以使用 mock/sample 数据跑通完整链路，后续再替换成可插拔真实采集模块。

## 3. 数据采集思路

系统关注京东、淘宝/天猫、拼多多、什么值得买和小红书。

京东适合获取自营保障、售后政策、评论和稳定价格。淘宝/天猫适合获取丰富套餐、店铺券、平台券和赠品。拼多多适合观察低价供给和拼团价，但要额外关注货不对板和退货风险。什么值得买适合参考历史好价和优惠路径。小红书适合补充真实使用场景和口碑，但不能作为价格或参数权威来源。

采集原则是优先官方开放平台、联盟 API 和公开数据源，不绕过登录、验证码和反爬限制。

## 4. 同款识别

同款识别是跨平台比价的前提。因为同一个帐篷在不同平台可能标题不同、套餐不同、赠品不同、规格不同，如果不先识别同款，直接比价会得出错误结论。

系统使用 SameProductScore：

- 0.30 × 品牌一致性。
- 0.25 × 型号关键词相似度。
- 0.20 × 标题相似度。
- 0.15 × 关键参数相似度。
- 0.10 × 图片/主图相似度占位。

分数 ≥85 自动归并，70-85 标记为疑似归并，<70 不归并。

## 5. 评论真实性识别

系统不默认所有评论都是真实评论。每条评论会计算 CommentCredibilityScore，考虑内容信息量、使用场景完整度、图文/追评证据、时间分布正常性、文本非模板化程度和多平台反馈一致性。

例如“还没用，先好评”这类评论权重很低；而“周末两人过夜，下雨后底帐边角渗水，有追评和图片”这类评论可信度更高。

## 6. 刷评过滤

系统会计算 FakeReviewRiskScore：

- 文本模板化程度。
- 时间异常程度。
- 低信息程度。
- 情绪过度正向但无细节。
- 同批评论相似度。

疑似刷评不会直接参与正向评分，或者只以很低权重参与。这样可以避免大量模板化好评把商品评分虚高。

## 7. 有效差评分析

差评也不是全部等权。系统把差评分为：

- 质量差评，例如漏水、断杆、拉链坏、结构倒塌。
- 参数虚标差评，例如空间偏小、防水虚标、重量偏重。
- 售后退货差评，例如质量问题不给退、退款慢、运费争议。
- 物流/个人偏好差评，例如快递慢、颜色不喜欢。

质量差评和售后差评对推荐影响最大，物流和个人偏好类差评扣分较低。

## 8. 价格优惠比较

项目区分两个价格：

- StableFinalPrice：稳妥到手价，普通用户较容易复现。
- TheoreticalLowestPrice：理论最低价，可能需要新人、会员、抢券、直播间或复杂凑单。

系统还会计算 CouponReliabilityScore，判断优惠是否稳定、是否需要特殊身份、是否需要抢券、是否需要复杂凑单。这样可以避免把很难复现的理论低价当作推荐依据。

## 9. 退货风险折算

帐篷问题经常在展开或使用后才发现，所以退货风险必须进入决策。系统会标准化字段，例如 7 天无理由、运费险、拆封后能否退、质量问题是否免费退、退款速度、是否全额退款、售后态度等。

然后计算：

- ReturnProtectionScore：退货保障分。
- ReturnRiskScore：退货风险分。
- ReturnRiskCost：把风险折算成金额。
- RiskAdjustedCost：风险调整后的真实购买成本。

因此最低价平台不一定是推荐平台。如果某个平台便宜 30 元，但退款慢、运费争议高、拆封后退货风险大，系统可能推荐价格略高但保障更稳的平台。

## 10. 场景化评分

不同用户场景权重不同：

- 新手公园露营：更重视搭建便利、空间、退货保障和价格。
- 过夜轻露营：更重视防水、防风、耐用和空间。
- 徒步轻量：更重视重量、收纳体积、防风和防水。
- 家庭多人露营：更重视空间、稳定性、耐用和售后。

系统不会用一套固定分数回答所有人，而是根据场景调整推荐。

## 11. 可解释推荐

每个推荐结果都必须解释：

- 为什么推荐这款帐篷。
- 为什么推荐这个平台。
- 为什么最低价平台不一定是推荐平台。
- 主要优点。
- 主要风险。
- 数据置信度。

例如系统可能输出：“这款帐篷适合新手公园露营，空间够用，搭建简单，评论中漏水反馈较少；虽然拼多多价格更低，但退货政策不清晰且退款慢差评较多，因此推荐京东自营购买。”

## 12. 项目亮点

- 不是简单爬虫，而是完整消费决策系统。
- 支持多平台数据标准化。
- 同款识别解决跨平台比价前提。
- 评论可信度和刷评风险降低虚假好评干扰。
- 有效差评分类让系统识别真正影响购买的风险。
- 区分稳妥到手价和理论最低价。
- 把退货风险折算成成本。
- 支持场景化评分，而不是单一排行榜。
- 推荐结果可解释，能说明推荐理由、避坑理由和数据置信度。

## 13. Agent 5 完整面试讲法

面试时我会先说明：CampRank 不是普通爬虫项目。普通爬虫通常停留在“把多个平台商品抓下来并展示列表”，但这个项目关注的是“如何把复杂、多源、可信度不一致的数据变成一个能解释的消费决策”。爬虫只是数据进入系统的一层，真正的核心是同款识别、评论可信度、刷评过滤、有效差评、平台优惠稳定性、退货风险成本和场景化评分。

第一版我选择先用 sample 数据跑通闭环，是因为推荐系统最怕一开始就被采集细节拖住。先把数据库、评论分析、评分、推荐 API、前端展示和测试链路跑通，可以验证字段设计和业务逻辑是否完整。后续真实采集只需要按标准字段接入，而不会影响评分和展示主流程。

评论可信度不是直接看星级，而是看评论有没有真实使用场景、天气、人数、搭建过程、追评或图片证据。像“好评”“物流很快”“还没用先好评”会被识别为低信息评论，权重很低。刷评过滤会看模板化文本、短时间集中发布、过度正向但没有细节、同批评论高度相似等特征，疑似刷评不会显著提高商品分。

差评也不是全部等权。系统会识别有效差评，把漏水、断杆、结构不稳、异味、空间虚标、收纳困难、防晒差、退款慢、不给退等风险拆成维度。质量和售后类差评会更影响推荐，物流慢或颜色不喜欢这类个人偏好风险扣分较低。

价格上项目区分稳妥到手价和理论最低价。稳妥到手价是普通用户更容易复现的价格，理论最低价可能依赖新人券、会员、直播抢券、限时红包或复杂凑单。系统会计算优惠可靠性，避免把不可复现的低价当成推荐理由。

最低价平台不一定是推荐平台，因为帐篷这种大件户外用品的售后风险很高。系统会把退货困难、退款慢、运费争议、客服扯皮、质量问题不给退等风险折算成 ReturnRiskCost，再进入 RiskAdjustedCost。举例来说，拼多多可能便宜 30 元，但如果退货政策不清晰、退款慢差评集中，风险调整后反而不如京东自营或天猫旗舰店稳妥。

场景化评分解决的是“不同用户要的不是同一款最优帐篷”。新手周末露营更重视搭建便利、空间、售后和价格；过夜轻露营更重视防水、防风和耐用；徒步轻量更重视重量和收纳；家庭多人露营更重视空间、结构稳定和售后。推荐结果最后不是只给一个分数，而是输出推荐平台、最低价平台、差价、优势、风险、数据置信度和为什么不一定推荐最低价，方便面试官看到系统的可解释性。
