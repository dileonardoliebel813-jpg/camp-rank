# CampRank 真实数据接入计划

## 当前执行范围：只接入京东

当前项目继续导入剩余数据时，只执行京东帐篷数据接入。淘宝/天猫、小红书、拼多多、什么值得买等多平台接入路径暂不执行，不能作为当前推荐依据。

本轮真实数据接入只允许使用：

- 京东商品 ID / pid。
- 京东商品标题、规格/套餐摘要、商品链接。
- 京东当前价格或最低套餐价。
- 京东评论正文、评分、追评、评论时间、图片数量、商家回复。
- 京东店铺名称和售后服务文本。

`redbook_notes` 保留为空数组；小红书样本缺失不再作为本轮数据置信度扣分项。任何缺失字段都必须保持缺失或 warning，不能补造。

## 1. 真实数据接入总原则

- 优先使用官方开放平台、联盟 API、授权数据、公开可访问且允许使用的数据源。
- 不使用登录态、验证码、Cookie、非公开内容或个人隐私数据。
- 不要求用户提供 Cookie、账号密码、验证码或个人隐私数据。
- 采集层只负责获取和标准化数据，不直接决定推荐结果。
- 缺失字段必须保留为空或默认缺失状态，不能假装完整。
- 缺失字段、样本不足、退货政策不清晰和京东评论不足都会降低 `data_confidence_score`；当前京东-only 流水线不因小红书样本缺失额外扣分。
- sample/mock 数据流程必须保留，用于演示、测试和离线开发。

## 2. 为什么先做 CSV/JSON 导入

第一阶段优先支持 CSV/JSON，是为了先跑通可验证的数据闭环：

真实整理数据 -> 字段校验与标准化 -> 写入现有数据库表 -> 评论分析 -> 评分计算 -> 前端展示。

这能避免把项目重点变成硬爬虫，也能让不同平台的数据在字段缺失、格式差异和来源可信度不一致时仍然进入统一流程。CSV/JSON 也适合人工复核、公开样例、平台开放 API 导出结果和后续批处理任务。

## 3. 各平台适配器边界

- `JDAdapter`：默认离线，只读取本地 JSON。未来如开启 `JD_API_ENABLED=true`，必须通过京东开放平台或联盟 API，不使用登录态或验证码。
- `SMZDMAdapter`：默认离线，只读取本地 JSON 好价记录。未来优先使用什么值得买开放平台或授权数据。
- `TaobaoAdapter` / `PddAdapter`：默认离线，只支持本地 JSON 导入。未来仅考虑官方开放能力、联盟 API 或授权数据。
- `RedBookAdapter`：默认离线。第一版只支持手动导入或开放平台授权数据，不做小红书公开笔记强爬。

## 4. 合规采集要求

- 不使用登录态。
- 不破解验证码。
- 不采集个人隐私。
- 不使用用户 Cookie、账号密码或验证码。
- 不规避访问频率限制。
- 公开网页解析只能作为补充手段，并必须尊重平台规则。
- 平台数据源需要记录来源、更新时间和字段缺失情况，便于追溯。

## 5. 字段缺失与数据置信度

真实平台数据不一定能拿到所有字段。导入层允许缺失字段，但会生成 warnings，并在后续评分中体现为更低的数据置信度。重点缺失项包括：

- 防水参数缺失。
- 重量或尺寸缺失。
- 退货政策字段缺失。
- 评论数量不足。
- 价格字段不完整。
- 当前京东-only 流水线不要求小红书样本。

评分脚本会基于参数完整度、有效京东评论数、京东价格字段、退货字段完整度和当前字段覆盖情况重新计算 `data_confidence_score`。

## 6. 后续平台接入路径

1. 继续扩展 CSV/JSON 字段映射，支持更多真实导出格式。
2. 为京东接入官方开放平台或联盟 API，将 API 返回结果转为统一 schema。
3. 为什么值得买接入开放平台或授权数据，用作历史好价和优惠稳定性参考。
4. 淘宝、天猫、拼多多、小红书仅保留为未来扩展规划；当前用户未要求时不要接入。
5. 每新增一个真实平台字段映射，都必须补充导入测试、adapter 测试和缺失字段测试。

## 7. 真实采集执行层补充

真实采集与离线导入必须严格区分：

- `live=false`：只读取本地 JSON/CSV 或 `backend/data/real_samples` 下的文件。这是本地文件导入，不是联网采集。
- `live=true`：调用平台 adapter 的 `fetch_live`，通过已配置的官方开放平台、联盟 API、授权 API 或用户自有合规 API URL 联网获取数据。

默认关闭真实 API 的原因：

- 避免在缺少授权、Key 或平台规则确认时误触发联网请求。
- 避免把 sample/mock 数据伪装成真实采集结果。
- 让测试和本地开发保持稳定、可复现。

各平台合规边界：

- 什么值得买：只通过配置的 `SMZDM_BASE_URL` 访问开放平台或授权 API，请求必须带 `SMZDM_API_KEY`。
- 京东：只通过配置的 `JD_BASE_URL`、`JD_API_METHOD`、`JD_APP_KEY`、`JD_APP_SECRET` 访问官方开放平台、联盟 API 或授权数据源。签名逻辑通过 `sign_params` 按实际官方方法扩展。
- 淘宝/天猫、拼多多、小红书：当前京东-only 流水线不使用这些入口，只保留历史扩展规划。

API Key 配置说明：

```bash
SMZDM_API_ENABLED=true
SMZDM_API_KEY=your_key
SMZDM_BASE_URL=https://your-authorized-smzdm-api.example/search

JD_API_ENABLED=true
JD_APP_KEY=your_app_key
JD_APP_SECRET=your_app_secret
JD_BASE_URL=https://your-authorized-jd-api.example/router
JD_API_METHOD=your.jd.method
```

真实采集失败排查：

- 检查 `*_API_ENABLED` 是否为 `true`。
- 检查 Key、Secret、Base URL、Method 是否完整。
- 检查平台授权是否覆盖当前接口和关键词搜索能力。
- 检查接口响应是否为 JSON，字段是否包含商品标题、平台商品 ID、价格、店铺、链接等必要信息。
- 查看 `FetchReport.errors` 和 `FetchReport.warnings`，不要用本地样例覆盖真实失败。

不能把离线样例伪装成真实采集结果。原因是 sample/mock 只用于演示、测试和离线开发，它无法证明价格、优惠、库存、评论或口碑在当前时间仍然有效。系统必须让用户清楚知道数据来自真实联网采集还是本地文件导入。
## 京东公开评价摘要接入边界

京东 SKU 评价数据接入只作为 CampRank 评论分析的数据来源之一，流程为：输入 SKU ID -> 低频公开数据读取 -> 本地 JSON 保存 -> 导入现有评论表 -> 继续运行评论分析和评分闭环。

该模块只允许读取公开可访问的评价摘要，并支持 `max_pages`、`page_size`、`delay` 和 `timeout` 等有限参数。默认行为是保存到本地 JSON：

```text
backend/data/real_samples/jd_comments_<sku_id>.json
```

导入数据库时，系统只根据 `sku_id` 匹配已有 `Product.platform_product_id`，不会强行创建商品。导入后的评价进入现有 `Comment` 表，可继续运行：

```bash
cd backend
python scripts/analyze_comments.py
python scripts/calculate_scores.py
```

合规和质量边界：
- 不使用账号、Cookie、验证码或非公开内容。
- 不承诺获取全部评价，只支持有限页数和有限数量的公开评价摘要。
- 遇到访问受限、登录页、验证码页、空响应或结构异常时立即停止并输出 warning。
- 字段缺失会进入 warning，并可能影响后续评论质量分析和数据置信度。
- 该数据只作为评论分析来源，不直接替代商品参数、价格、售后政策或最终推荐结论。

## 京东帐篷本地表格 MVP 通道

当前京东帐篷商品使用本地 `data.xlsx` 或用户提供的京东表格生成标准 JSON，再通过现有导入、评论分析、评分和前端展示闭环处理。该流程只使用本地文件，不进行真实联网请求。

详细执行步骤、字段要求、清洗规则、客观评论证据评分方式和后续复用方式见：

```text
docs/jd_mvp_review_scoring_and_ingestion.md
```

该 MVP 的核心边界：

- 评论只作为校准后的风险证据，不直接等同商品质量结论。
- 原始好评/中评/差评比例会保留，但评分使用统一的标准化权重进行比较。
- 缺少防水、重量、尺寸、材质等硬参数时，不补造字段，并降低数据置信度。
- 后续新表格应先转换为 CampRank 统一 JSON，再进入现有 Comment 表、评论分析和评分通道。
